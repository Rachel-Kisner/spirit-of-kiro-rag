6A. Retry / Query Rewriting LLM + LlamaIndex Workflow If retries remain (maximum 2 additional attempts), the LLM rewrites the original question. RetryEvent triggers another Pinecone retrieval and validation cycle.
If the retry limit is reached, or no different query can be generated, the workflow returns an explanatory StopEvent.
↓
7A. Answer Synthesis LlamaIndex Response Synthesizer + LLM Generates an answer using the validated retrieved Nodes and the user's query.

4B. Structured Route

For questions asking for specific records, categories, keywords, or counts

↓
JSON Retrieval structured_retriever.py + Python Executes the structured query against extracted_data.json and returns matching records.

8. Final Result – StopEvent LlamaIndex Workflow Returns the generated answer or the relevant validation / no-results message to the caller.

Component responsibilities

  • LlamaIndex Workflow: Orchestrates steps, events, and workflow state through Context.
  • Pinecone: Stores document vectors and performs vector similarity search.
  • LlamaIndex Retriever: Connects the semantic retrieval step to the vector store.
  • Cohere: Creates document embeddings during the preparation/indexing stage; it is not the retrieval database.
  • validators.py: Validates the input and, on the semantic path, the retrieved Nodes and retrieval confidence.
  • LLM: Supports routing (depending on router.py implementation), query rewriting, structured-query generation, and answer generation.
  • Response Synthesizer: Uses the retrieved semantic Nodes to synthesize a grounded response with the LLM.
  • Python: Executes structured JSON filtering and handles count questions.

Based on the supplied workflow.py implementation. Cohere embedding generation belongs to the preparation/indexing stage, before this runtime workflow.
